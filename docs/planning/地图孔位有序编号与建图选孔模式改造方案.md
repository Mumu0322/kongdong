# 地图孔位有序编号与建图选孔模式改造方案

## 1. 背景和目标

2026-09-15 的扇区 S01 建图运行 `two-stage-20260915_164810` 自动选中了 50 个孔。前 9 个共享粗定位组完成后，第 10 组在 340 mm 观察位现场纠偏阶段触发控制器碰撞标志，程序停止了后续运动，地图没有发布为新的当前地图。

本次改造解决三个问题：

1. 地图内孔号按画面位置排列，采用“从上到下逐行、每行从左到右”的顺序生成 H01、H02……；编号不再取决于 YOLO 返回顺序、置信度或鼠标点击顺序。
2. 选定扇区后，操作者可以选择“自动选孔建图”或“人工选孔建图”。两种模式共用同一套候选过滤、编号和地图格式。
3. 建图运动在下发前增加预检和分阶段安全路径；现场纠偏超过限制时停止该组并要求人工处理，不继续自动横移或调姿。

本文把“从上往下，从左到右”解释为：先按图像 Y 坐标从小到大划分行，再在每一行内按图像 X 坐标从小到大编号，即常见的逐行阅读顺序。如果现场要求的是“先一列从上到下，再向右换列”，只替换排序策略，其他设计不变。

## 2. 当前行为和问题原因

### 2.1 孔号目前不是空间顺序

自动分区在多边形模式下会先过滤区域外、低置信度和重复候选，但最终排序字段是：扇区号、径向距离、角度、检测索引。多边形模式没有径向距离和角度，因此同一扇区实际上退化为按 YOLO 的检测索引排序。

初始选孔流程随后直接按这个列表 `enumerate(..., start=1)` 生成 `hole_id`。因此当前 H01、H02……本质上接近模型输出顺序，画面位置是乱的。人工模式下则接近鼠标点击顺序，同样不能保证空间有序。

### 2.2 自动分区和自动选孔绑在一起

现有 GUI 只有“启用静态伞架自动扇区划分和自动选孔”开关。启用后，区域内所有通过过滤的候选直接进入建图链路；操作者无法在完成扇区归属后选择“全部自动采用”或“只采用人工点选的孔”。

### 2.3 当前安全高度不能证明路径无碰撞

本次碰撞发生在第 10/10 组现场纠偏。日志显示，程序先从 TCP 基坐标 Z≈86.0 mm 纯 Z 抬升到 Z≈135.3 mm，下一段准备在该高度横移并改变姿态时控制器报告碰撞。此前 9 组已经完成，本轮累计规划 TCP 路径约 5.12 m。

现有路径使用“目标观察位 Z + 60 mm”作为局部安全高度。这个规则能避免低位直接横移，但不能证明机器人本体、夹爪、相机和工装在关节运动过程中没有碰撞，也没有限制现场纠偏产生的平移量和姿态变化量。

## 3. 目标交互流程

### 3.1 GUI 流程

“粗定位地图”区域增加“建图选孔方式”单选项：

- `自动选择本扇区全部合格孔`：采用本扇区内通过 ROI、置信度、边界和去重规则的全部候选。
- `人工选择本扇区孔`：先完成自动检测和扇区归属，只把本扇区合格候选显示给操作者；操作者点击选择或取消，按 Enter 确认。

推荐默认值为“人工选择本扇区孔”。发生过碰撞后，不应让新建图默认进入全自动大批量运动。

两种模式都必须经过以下步骤：

1. 读取当前扇区编号和对应观察位记录。
2. 采集一张初始 RGB-D 图，完成 YOLO 检测、扇区归属、质量过滤和去重。
3. 根据选孔方式得到最终候选集合。
4. 对最终集合执行空间排序并生成 H01、H02……。
5. 显示带孔号的编号预览图，列出孔数、行数、每行孔数和被排除候选。
6. 操作者确认编号与选孔结果后，才允许生成运动分组并进入真实建图。
7. 如果取消确认，本轮保存预览和审计 JSON，机器人不运动，地图不发布。

“自动选择”表示软件自动确定候选集合，不表示自动跳过最终安全确认，也不表示无人值守运动。

### 3.2 命令行接口

增加一个只在建图模式生效的参数：

```text
--map-hole-selection-mode auto|manual
```

- `auto`：自动采用本扇区全部合格孔。
- `manual`：在本扇区候选中人工点选。

GUI 必须显式传递该参数。普通两阶段定位、地图调用和单孔返修不读取它，避免改变现有流程。

## 4. 孔位排序和编号设计

### 4.1 排序输入

编号仅使用本次确认后的候选及其初始观察图像坐标：

- `center_px = [x, y]`
- 检测框宽高
- `sector_id`
- 原始 `detection_index`

`detection_index` 只用于追溯和最终平局，不再作为主要编号依据。

### 4.2 自适应逐行排序

建议新增纯函数 `order_holes_row_major(candidates)`：

1. 计算候选检测框高度的中位数，得到当前画面的孔尺度。
2. 先按中心 Y 从小到大排列。
3. 用自适应行容差把 Y 接近的孔归入同一行。行中心使用该行所有孔 Y 的中位数，避免单个检测抖动拉偏整行。
4. 行按中心 Y 从小到大排列。
5. 每行内按中心 X 从小到大排列。
6. 依次赋值 `hole_id=1..N`；完全重合时才用 `detection_index` 保证结果确定。

行容差不写死为固定像素，而是由孔框中位高度和候选 Y 间距共同估计，并设置合理上下限。这样同一逻辑可以覆盖不同分辨率和相机距离。具体系数通过当前 50 孔图、已有 S01 图和合成抖动用例确定。

### 4.3 编号与执行顺序分离

地图身份和机器人访问顺序必须是两个字段：

- `hole_id` / `map_order`：固定使用空间编号，决定 H01、H02……。
- `execution_order`：由分组、路径优化或操作者选择决定，可以与孔号顺序不同。

批量分组可以为了视野和路程改变访问顺序，但不能重写地图孔号。报告同时保存 `map_order` 和 `execution_order`，防止把“第几个执行”误当成“孔号”。

### 4.4 地图记录

每个孔增加以下审计字段：

```json
{
  "hole_id": 1,
  "map_order": 1,
  "layout_row": 1,
  "layout_column": 1,
  "numbering_center_px": [x, y],
  "numbering_policy": "image_row_major_v1",
  "selection_source": "auto" 
}
```

人工模式的 `selection_source` 为 `manual`。地图级别保存：

- 编号规则和版本；
- 初始图像尺寸；
- 行容差及推导依据；
- 每行孔数；
- 编号预览图路径；
- 候选总数、采用数和排除原因。

成功建图生成新的版本目录；不在原地图文件上原地改号。旧地图仍可回退。单孔返修沿用原 `hole_id`，不能重新排序整个扇区。

## 5. 人工选孔模式细节

人工选孔窗口只允许选中当前扇区内、已通过基本质量过滤的候选：

- 合格未选：黄色框；
- 已选：绿色框；
- 区域外、边界待确认或被去重：灰色/红色且不可选，并显示原因；
- 鼠标点击切换选择状态；
- Enter 完成，Esc 取消本轮。

人工点击顺序只表达“选或不选”，不决定孔号。确认后统一执行逐行排序。这样操作者可以任意点击，地图仍保持从上到下、每行从左到右。

如果只选部分孔，所选孔连续编号为 H01..HN。后续重新建图并增删孔时，编号可能变化，因此发布前必须重新看编号预览；已经发布地图上的孔号在单孔返修中保持不变。

## 6. 建图运动安全改造

### 6.1 建图前预检

编号确认后先生成完整的分组和运动计划，不立即运动。每组至少显示并记录：

- 包含的地图孔号；
- 名义观察 TCP；
- 与上一组的 XY、Z 和姿态变化；
- 计划的撤离、过渡和下降路径；
- 是否超过工作区、姿态或纠偏门限；
- 当前控制器是否上电、稳定、无碰撞且处于安全范围。

任一目标无效或超过限制时，整轮保持在“计划未通过”状态，不下发第一条运动。

### 6.2 使用现场示教的安全过渡位

仅用“目标 Z + 60 mm”不能代表安全。每个扇区应增加一个由现场示教并验证的 `sector_safe_waypoint`，至少保存关节位姿、对应 TCP、机器人/TCP/夹爪身份和验证时间。

推荐组间路径：

```text
当前观察位
  → 当前姿态纯 Z 撤离到安全净空
  → 经本扇区已示教安全关节位
  → 在安全区完成必要调姿
  → 移动到目标上方
  → 保持 XY/姿态纯 Z 分段下降到观察位
```

如果没有已验证的扇区安全位，真实建图按钮保持禁用或只允许逐组人工确认的低速验证模式。

### 6.3 限制现场纠偏

现场纠偏只允许小范围修正。增加独立门限：

- 最大 XY 修正；
- 最大 Z 修正；
- 最大 Rx/Ry 姿态修正；
- 单次和累计修正次数；
- 修正目标的工作区和控制器安全范围检查。

超限时将该组标记为 `deferred_pose_correction_requires_manual_review`，保存观测和建议目标，不执行修正运动，也不继续后续组。初始门限应在无工件或充分降速的现场验证中确定，不能仅凭离线数据给出“绝对安全”的数值。

纠偏路径应把“调姿”和“横移”拆开，避免在低净空的一条 Cartesian 直线中同时大幅改变位置和姿态。若 AUBO 当前 SDK/控制器能够提供逆解、关节限位或轨迹检查接口，再把它接入预检；现有 `isWithinSafetyLimits()` 只检查当前状态，不能替代未来整条路径的碰撞检查。

### 6.4 逐组确认和故障记录

首轮验证阶段默认逐组确认，界面显示“下一组孔号、目标姿态、预计位移”。完成若干轮无碰撞验证后，才考虑允许同一扇区自动连续建图。

碰撞或运动失败时必须：

1. 立即停止并禁止后续运动；
2. 记录失败组、失败子步骤、起点、目标、实测 TCP 和控制器状态；
3. 将会话状态写成 `robot_motion_failed`；
4. 不发布新的 `current.json`；
5. 保留已经完成组的诊断数据，但不得把部分地图标成可调用地图。

## 7. 代码修改位置

预计涉及：

- `aubo_workbench/auto_sector_selection.py`
  - 增加逐行空间排序函数；
  - 自动候选仍负责分区、过滤和去重，不再决定最终地图号。
- `aubo_workbench/hole_capture_workflow.py`
  - 接收建图选孔模式；
  - 人工模式调用候选选择窗口；
  - 选择结束后统一重排并赋 `hole_id`。
- `aubo_workbench/gui_hole_localization.py`
  - 增加“自动全部/人工选择”控件；
  - 增加编号预览和确认状态；
  - 未确认编号时禁止真实建图。
- `aubo_workbench/hole_localization_cli.py`
  - 增加 `--map-hole-selection-mode`。
- `aubo_workbench/hole_map.py`
  - 保存并校验编号元数据；
  - 保证地图键 Hxx 与 `hole_id` 一致；
  - 单孔返修保持旧编号。
- `aubo_workbench/group_pose_workflow.py`、`motion_control.py`
  - 增加扇区安全位、纠偏门限和运动前计划检查；
  - 拆分高位调姿与横移；
  - 完善失败运动审计字段。
- `run_yolo_eye_in_hand_optimized.py`
  - 在建图入口串联选择、编号确认、预检和执行阶段。

## 8. 测试与验收

### 8.1 离线测试

新增测试至少覆盖：

1. 多行规则网格按上到下、行内左到右编号。
2. 行内存在像素抖动、透视倾斜和交错孔时仍保持稳定行归属。
3. YOLO 输入顺序和置信度随机变化时，输出孔号不变。
4. 人工点击顺序变化时，最终地图编号不变。
5. 人工选择子集时编号连续、未选孔不写地图。
6. 自动与人工选择相同集合时，编号完全一致。
7. 编号确认前不产生机器人运动命令。
8. 纠偏超过门限时不发送运动，并写出 deferred 原因。
9. 碰撞后不执行下一组、不发布 current 地图。
10. 单孔返修保持既有孔号。

全量回归基线为当前的 `344 passed, 1 skipped, 8 subtests passed`。

### 8.2 现场验收顺序

1. 使用当前 50 孔初始图做纯离线编号预览，人工核对 H01..H50。
2. 分别验证自动全选和人工子集，不连接运动控制。
3. 生成完整分组及路径预览，检查第 10 组和本次碰撞附近姿态。
4. 无工件或安全隔离条件下，低速逐组验证扇区安全位和纠偏门限。
5. 单组建图，确认地图不包含未选孔且编号正确。
6. 少量组建图，再扩大到完整扇区。
7. 完整建图后检查新版地图、编号预览、点云产物和 `current.json` 指针。

## 9. 完成标准

满足以下条件后才算改造完成：

- 同一候选集合无论检测返回顺序、置信度或点击顺序如何，地图孔号均按空间顺序稳定生成。
- GUI 明确支持自动全选和人工选孔，两种模式在编号确认前都不运动。
- 地图号与执行顺序彻底分离，地图调用和单孔返修不破坏编号。
- 超限纠偏在下发前被拒绝；碰撞后没有后续运动，也不会发布部分地图。
- 离线回归通过，并完成从单组到完整扇区的分级现场验证。
