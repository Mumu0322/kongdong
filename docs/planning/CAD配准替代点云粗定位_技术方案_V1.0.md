# 用 CAD 配准替代点云粗定位 —— 技术方案

## 0. 文档说明

本方案基于本次上传的资料包（`cad_coarse_localization_plan_package`）编写，包括：

- 真实 STEP 文件：`孔位板_JXDZ26-KWB-001.STEP`（此前资料包中缺失，本次已补全并被本方案实际读取解析，而不是按记忆假设）；
- 现有主流程源码 `run_yolo_eye_in_hand_optimized.py` 及 `aubo_workbench/` 全部模块；
- 手眼、内参、精度诊断等 evidence 数据。

方案中所有涉及 CAD 数值的部分，均来自对 STEP 文件的**程序化几何解析**（而非人工读图或记忆），解析方法见附录 A，以便你或 Codex 复核。所有涉及现有代码行为的描述，均标注了源文件与函数名，便于 Codex 直接定位、最小化改动范围。

本方案不包含代码，只包含可直接转化为实现任务的设计决策、接口约定、阈值与验收标准。

## 1. 目标与不可改变的边界

替换目标：`run_yolo_eye_in_hand_optimized.py` 中 **RGB-D 点云粗定位** 这一段，包括：

- `_capture_coarse_burst`：在约 340 mm（`TwoStageConfig.coarse_height_mm`）反复采集深度环带、拟合局部切平面；
- `_apply_coarse_geometry_to_hole` + `_fuse_coarse`：把多帧点云平面结果融合成 `coarse_center_base_mm` / `coarse_normal_toward_camera_base`；
- 每孔在 340 mm 高度的闭环居中（该闭环是"慢"的主要来源）。

替换为：**一次 CAD 配准**（同一 home 帧上，对可见的大孔做 PnP 位姿求解），直接产出与原来 `coarse_center_base_mm` / `coarse_normal_toward_camera_base` **同名同义**的 11 个孔的基坐标系坐标和法向，直接喂给精定位阶段的位姿规划函数 `_plan_hole_tcp_pose_fixed_rz(..., camera_height_mm=cfg.fine_height_mm)`，机械臂从 home 直接下探到精定位高度（约 260 mm），不再经过 340 mm 闭环。

**必须原样保留、本方案不触碰的下游环节**（均已在现有代码中实现，CAD 配准只是替换它们的输入来源）：

| 环节 | 现有函数 | 说明 |
|---|---|---|
| RGB YOLO + 椭圆拟合精定位 | `fit_hole_ellipse`、`_capture_fine_burst`、`_fuse_fine` | 不改动，只做最终 XY 修正 |
| 最终 Z 规划 | `plan_final_tcp_base_z` | 不改动 |
| 机械爪 X/Z 偏置 | `apply_final_point_base_offsets`、`final_point_offsets_for_mode` | 不改动 |
| 基坐标 +Y 0.3 mm | `plan_final_tcp_base_y_trim`（`FINAL_BASE_Y_AFTER_Z_MM`） | 不改动 |
| ChArUco TCP-XY 补偿 | `record_tcp_absolute_xy_model.py` 相关模型 | 不改动，在最终 XY 之后按现有方式应用 |
| 运动前人工确认/安全快照 | `_require_safe_snapshot`、`_request_motion_confirmation`、`_confirm_and_move_line` | 不改动，CAD 配准阶段同样禁止无确认自动运动 |

**第一阶段（Stage 0）硬性要求**：CAD 配准功能只做离线预览（读取一张真实 RGB 图 + 已知的近似 `T_base_camera`），输出叠加图和 JSON 报告，**不得连接、不得驱动机械臂**。这与资料包 `README_FOR_PLANNER.md` 的要求一致。

## 2. 从 STEP 实测得到的 CAD 数据（权威数据源）

### 2.1 解析方法

使用 `OCP`（OpenCascade Python 绑定）加载 STEP，遍历所有面（`TopAbs_FACE`），筛选圆柱面（`GeomAbs_Cylinder`）确定各孔位置和大致半径分组；再遍历所有边（`TopAbs_EDGE`），筛选圆形边（`GeomAbs_Circle`）中位于顶面（Z=6mm）、半径 > 25mm 的边，得到**顶面可见孔口边界**——这才是相机实际能看到、YOLO/椭圆拟合实际检测到的那个圆，而不是孔内部台阶/沉孔的圆。方法与代码见附录 A，Codex 可直接复用同一段解析逻辑生成正式的孔位 JSON。

### 2.2 关键确认结论

- 板材整体外形包围盒：X ∈ [-215, 215]，Y ∈ [-140, 140]，Z ∈ [0, 6]（单位 mm）。CAD 原点位于板材俯视轮廓的**几何中心、底面**（不是安装孔或某个角）。
- **顶面高度 Z = 6 mm，法向 +Z**：与之前口头记忆一致，本次已用真实几何独立验证，不再是假设。
- 板上共有 **11 个顶面大孔**，均为台阶孔（上方大直径、下方小直径，用于坐台阶/沉入光学件），孔轴方向为 -Z（从顶面向下打），与 README 描述一致。
- 顶面孔口（相机可见、算法应匹配的目标）直径分 **3 档**：Φ68.5 / Φ73.5 / Φ78.5 mm。

  **⚠️ 需要你确认的偏差**：此前记忆中提到的镀膜伞架三种孔径为 65/70/75 mm，与本次实测的 68.5/73.5/78.5 mm 相差约 +3.5 mm（三档同幅偏移，像是统一的余量或不同工序尺寸）。请确认：(a) 这块 `JXDZ26-KWB-001` 孔位板是否就是生产用的工件本身，还是一块专用的相机标定/验证板；(b) 若是生产工件，65/70/75 是设计名义值、68.5/73.5/78.5 是 CAD 实际建模值，两者哪个用于程序里的直径判据。这个数字会被用作身份消歧的弱证据（见 5.2），数值不对不会导致崩溃，但会削弱消歧能力，建议开工前确认。

布局特性（对 5.2 节的消歧设计很重要）：

- 三行结构：Y = -90 / 0 / 90，行间距 90 mm；每行内相邻孔中心间距 100 mm。

## 3. 坐标系与单位约定（强制统一，防混淆）

| 坐标系 | 定义 | 现有代码中的载体 |
|---|---|---|
| CAD 坐标系 | 板材底面几何中心为原点，见 2.1 | 新增，来自 STEP |
| 相机坐标系 | Orbbec 光心，Z 轴指向前方（远离相机为正） | `camera.py` intrinsics 相关 |
| TCP 坐标系 | 机械臂末端工具坐标 | `robot.py` / `motion_control.py` |
| 基坐标系 Base | 机械臂基座 | 现有代码全流程的目标坐标系 |

强制规则：

1. **全程使用毫米**。唯一允许出现米/弧度的位置是 SDK 边界函数 `transform_to_sdk_pose_m_rad`，新增代码禁止自己做单位换算，一律复用现有工具函数（`camera_transform`、`camera_ray`、`undistort_pixels`、`make_transform` / `invert_transform`）。
2. **法向"朝向相机"的判定规则复用现有实现**，不要重新发明：`_apply_coarse_geometry_to_hole` 中的判据——`if normal_base @ (camera_origin - point_base) < 0: normal_base = -normal_base`。CAD 法向变换到基坐标系后必须套用同一判据。
3. 每次读取机械臂位姿必须与图像采集**同一时刻**，复用现有 `_require_safe_snapshot` 的"位姿+图像一起拿"模式。资料包记忆中提到的 `_capture_coarse_burst` 坐标域不一致 bug，根因就是位姿快照和图像不同步；CAD 配准新代码要从设计上规避同类问题。

## 4. 总体流程（替换后）

1. 机械臂回到 `aubo_home_point.json` 定义的原始点（沿用现有 `_confirm_and_move_home`，不改）。
2. 在 home 位姿采集 **5 帧** RGB（沿用现有"多帧+质量门"风格，不是只拍 1 帧）。
3. 对每一帧独立执行"检测→匹配→PnP→质量门"，得到该帧的 `T_camera_cad` 候选（详见第 5 节）。
4. 至少 3/5 帧通过单帧质量门时，跨帧融合得到最终 `T_camera_cad`；否则整体判定 CAD 配准失败，阻断运动（第 5.7 节）。
5. 用同一时刻记录的 `T_base_tcp`（home 位姿）与手眼 `T_tcp_camera`，组合得到 `T_base_cad`。
6. 用 `T_base_cad` 把 **11 个 CAD 孔**（不只是当帧看到的几个）批量变换到基坐标系，得到每个孔的 `point_base_mm` 和 `normal_toward_camera_base`。
7. 对每个孔调用现有 `_plan_hole_tcp_pose_fixed_rz(point_base_mm, normal_toward_camera_base, reference_T_base_tcp, T_tcp_camera, camera_height_mm=cfg.fine_height_mm)`，直接得到该孔在**精定位高度（约 260 mm）**的目标 TCP 位姿——**跳过 340 mm 闭环粗定位**。
8. 机械臂逐孔运动到该位姿（沿用现有确认/安全门），进入现有 RGB 精定位、最终 XY/Z/爪偏置/+Y 0.2mm 流程，完全不变。

这一步把 CAD 配准的输出边界，刻意设计成与现有代码里 `hole["coarse_center_base_mm"]` / `hole["coarse_normal_toward_camera_base"]` 完全同构，这样 Codex 实现时可以让 CAD 配准模块"顶替"`_apply_coarse_geometry_to_hole` 的输出，而不用改动它下游的任何函数签名。

## 5. 算法细节

### 5.1 图像点提取与去畸变

- 检测大孔仍用现有 YOLO 模型（`small_silu.pt`）得到候选框，再用现有 `fit_hole_ellipse` 做亚像素椭圆拟合，取椭圆中心作为图像观测点（比 YOLO 框中心精度高，复用现成函数，不新写检测逻辑）。
- 去畸变复用现有 `undistort_pixels`（内参见 `evidence/handeye/current_rgb_intrinsics.json`：`fx≈610.05, fy≈610.27, cx≈648.24, cy≈406.75`，畸变 `[-0.03353, 0.03747, 0.000202, -0.0000999, -0.01324]`）。PnP 全程在去畸变后的归一化/像素坐标系里做，不要混用原始畸变像素坐标。

### 5.2 CAD 孔与检测框的唯一匹配（含对称消歧）

**核心原则：绝不允许程序在对称解之间"任选一个"。** 消歧必须依赖一个独立的先验信息源——机械臂当前的正向运动学位姿（`T_base_tcp`，home 点已知）与现有手眼 `T_tcp_camera`（哪怕手眼还未最终验证，粗略量级也足够用于消歧，见 5.4 的分级使用说明）算出的 `T_base_camera_fk`。

流程：

1. 用 `T_base_camera_fk`（此时还没有 CAD 配准结果，只是"猜的"）把 11 个 CAD 孔中心批量投影到图像平面，得到 11 个"预测像素位置"。
2. 用现有检测+椭圆拟合，得到当帧实际观测到的若干孔的图像中心。
3. 做**预测点 ↔ 观测点的最近邻匹配**，并要求互为最近邻（mutual nearest neighbor）、匹配距离低于一个像素阈值（初始建议 80 px，见 5.6 阈值推导）。
4. 直径弱校验：观测椭圆的像素直径应与"预测直径"（CAD 直径 × 当前 FK 估计高度下的 GSD 倒数）落在合理比例区间内（建议 ±25%），用于剔除明显误匹配，不作为唯一判据。
5. 剔除近共线的匹配点（任意三点组成三角形面积过小则整体判定该帧点位分布不足，见 5.6），因为共线点做平面 PnP 时姿态会病态。
6. 要求**匹配数 ≥ 4**（PnP 最低要求），**优先要求 ≥ 6**（更稳，可以用迭代法而不是只依赖 IPPE 的两解歧义）。

这个设计的关键在于：**即使 FK+手眼算出来的"先验位姿"本身有几十毫米甚至更大的误差，只要它比"孔间最小距离 100 mm 的一半（50 mm）"精确得多，就足够正确地把左右对称的孔分开、不会匹配错**。这是本方案能够绕开对称消歧问题的根本原因，而不是靠猜测孔号。

对漏检、误检的处理：漏检的 CAD 孔本轮直接跳过、不强求全部 11 个都出现在当帧；误检（检测到孔位板以外的伪目标）会因为投影距离过远、直径不符而被步骤 3、4 自然剔除，不需要额外的误检专用逻辑。

### 5.3 平面 PnP 求解

- 因为 11 个孔在 CAD 坐标系下严格共面（Z 恒为 6），使用 **共面 PnP**：`cv2.solvePnPGeneric(..., flags=cv2.SOLVEPNP_IPPE)`（4 个匹配点时）或匹配点 ≥ 6 时改用 `SOLVEPNP_ITERATIVE`（以 IPPE 结果作初值），输入去畸变后的归一化坐标、`distCoeffs=0`。
- `SOLVEPNP_IPPE` 对平面目标天然返回 2 组解（近正视角时两个重投影误差可能都很低，这是平面 PnP 的固有二义性，不是 bug）。**不要只取重投影误差更低的那组**，而是用 5.2 中已经算出的 `T_base_camera_fk` 做二次筛选：对每组候选解算出对应的 `T_base_cad_candidate`，取其法向变换到基坐标系后与 `T_base_camera_fk` 隐含的"预期法向朝向"（大致 -Z_base，即孔面朝上、相机朝下俯视）夹角更小的那一组。
- 求解结果记为 `T_camera_cad`（把 CAD 坐标系下的点变换到相机坐标系：`X_camera = R · X_cad + t`），命名与现有代码里 `T_base_camera` / `T_tcp_camera` 的命名风格保持一致。

### 5.4 T_camera_cad → T_base_cad 的组合与手眼质量的分级使用

组合关系：

```
T_base_cad = T_base_tcp(采图瞬间) · T_tcp_camera(手眼) · inverse(T_camera_cad)
```

`T_base_tcp` 必须来自**同一次安全快照**（`_require_safe_snapshot`）里和图像一起拿到的位姿，不能事后用当前位姿或缓存位姿代替。

**关于当前手眼状态的分级使用**：`evidence/handeye/e7_handeye_candidate_current.json` 显示当前 E7 手眼候选 `validated=false`、`do_not_use_for_motion=true`，不能作为生产运动依据。因此本方案把手眼用在两个不同严格度的地方：

- 5.2 节的"先验位姿投影"用于对称消歧——这里只需要粗略量级（几十毫米误差可接受，见上），可以用当前未验证的手眼候选，风险可控；
- 5.4 节这里组合出的 `T_base_cad` 会**直接决定机械臂运动目标**——这里必须使用已经过质量门验证的手眼结果（沿用你项目里已有的门槛：平移均值 < 5 mm、法向均值 < 2°）。

也就是说：**在手眼正式验证通过之前，CAD 配准可以先在 Stage 0/Stage 1（离线预览、影子模式）跑通算法和消歧逻辑，但不能进入 Stage 2（真正接管运动）**。这是本方案对"CAD 配准依赖手眼精度"这一系统性风险的处理方式，而不是回避它。

### 5.5 多帧采集与融合（5 帧、3/5 质量门）

- 沿用现有代码"多帧+提前收敛+质量门"的风格（对照 `coarse_frames`/`min_coarse_valid`/`_coarse_burst_stable`），CAD 配准阶段建议：`cad_frames=5`，`min_cad_valid=3`（3/5 通过即可提前结束，不必等满 5 帧）。
- 单帧"通过"定义：完成 5.2~5.3 全流程、且满足 5.6 节单帧阈值。
- 跨帧融合：对通过质量门的各帧 `T_base_cad`，平移取中位数（复用现有 `_fuse_vectors` 风格），旋转取四元数意义下的鲁棒平均（现有 `_fuse_normals` 只针对法向量，这里需要新增一个"旋转矩阵/四元数鲁棒平均"的小工具函数，逻辑与 `_fuse_normals` 的鲁棒思路一致，可直接对齐实现）。
- 跨帧一致性质量门：各通过帧算出的 11 个孔基坐标系中心，逐孔计算跨帧 P95 偏差，需低于阈值（见 5.6）。

### 5.6 质量门与阈值（含推导依据）

| 门限 | 建议初始值 | 依据 |
|---|---|---|
| 单帧匹配点重投影 RMSE | ≤ 1.5 px | 略宽于精定位阶段的 `max_ellipse_residual_px=0.9`，因为 CAD 配准现在承担的是"粗定位"角色，不需要精定位级别的严苛度，但要比旧点云粗定位明显更准 |
| 单点最大重投影误差 | ≤ 3.0 px | 同上，防止个别误匹配拉低整体 RMSE 却仍通过 |
| 最近邻匹配距离阈值 | ≤ 80 px | 见下方 GSD 推导 |
| 最少匹配点数 | ≥ 4（硬性），< 6 时禁用 ITERATIVE 只用 IPPE+先验消歧 | PnP 数学要求 |
| 匹配点最小分布（防共线） | 任意三点三角形面积 ≥ 一个下限（建议不小于按最小孔距 100 mm 换算出的图像面积的 10%） | 防病态解 |
| 单帧通过数 | ≥ 3 / 5 帧 | 与现有粗/精定位"多帧+质量门"风格一致 |
| 跨帧孔位 P95（基坐标系） | ≤ 1.5 mm | CAD 配准是开环单发，必须比旧的迭代闭环更稳，才有资格直接送到精定位 |
| CAD 配准结果与精定位落点的总误差预算 | ≤ 20 mm（硬阻断），目标 ≤ 10 mm | 见下方精定位捕获范围推导 |
| `T_camera_cad` 平移 Z 合理范围 | 400–650 mm（按实际 home 高度校准） | 防止病态解给出不合理深度 |

**GSD（地面采样距离）推导**（`fx≈610.05`）：

- 精定位高度 260 mm：GSD ≈ 0.426 mm/px；现有 `fine_pointcloud_anchor_tolerance_px=30 px` 对应约 12.8 mm 的身份锚定容忍半径。
- 粗定位高度 340 mm：GSD ≈ 0.557 mm/px；现有 `multi_coarse_tracking_tolerance_px=70 px` 对应约 39 mm。
- home 高度按 500–600 mm 估计：GSD ≈ 0.82–0.98 mm/px，80 px 对应约 66–79 mm——这是 5.2 节最近邻匹配阈值取 80 px 的依据（先验位姿允许有几十毫米误差，仍能正确匹配，因为最小孔距有 100 mm）。

**精定位捕获范围推导**（回答"CAD 配准精度要做到多少才够"）：CAD 配准只需要把机械臂送到一个位置，使现有 RGB 精定位阶段（`_capture_fine_burst` + 身份锚定容忍 `fine_pointcloud_anchor_tolerance_px=30px≈12.8mm`）能正确锁定并收敛到目标孔，而不需要自己达到最终精度。孔心最小间距 100 mm，只要 CAD 配准误差明显小于半间距 50 mm，就不会认错孔。因此把 20 mm 设为硬阻断上限（仍有 30 mm 安全裕度），10 mm 作为期望目标（给精定位留出充足的收敛空间，也给未来手眼/相机漂移留余量）。

以上数值均为**建议初始值**，需要在 Stage 1 影子模式下用真实数据回填校准（见第 8 节）。

### 5.7 失败阻断策略

- 任一环节失败（匹配点不足、PnP 病态、单帧门限不过、3/5 帧不过、跨帧一致性不过、深度或法向不合理）：**直接判定 CAD 配准失败，不产出任何 `point_base_mm`/`normal_base`，不调用任何运动函数**。
- 失败时仍要落盘：叠加图 + JSON 报告（见第 6 节），并给出人类可读的失败原因（复用现有代码里 `raise RuntimeError(f"...")` 的中文错误信息风格）。
- 是否自动回退到旧的点云粗定位：**方案建议第一阶段不做自动回退**，失败即停止、需要人工介入重拍或检查（更安全、便于早期发现算法问题）；等 Stage 2 运行足够稳定后，可以再考虑在配置里加一个可选的"CAD 配准失败时自动回退点云粗定位"开关，默认关闭。

## 7. 仍需你确认或补充的信息

1. **CAD 孔号 ↔ 现场物理孔号的对照表**：本方案的 CAD-01~CAD-11 是纯几何位置编号，不代表现场任何已有编号体系。需要你确认这块板安装到机械臂工作台后的实际朝向（哪条边朝向机械臂 +X/+Y），才能把 CAD 坐标系原点/朝向和机械臂基坐标系正确对齐——这一步无法从 STEP 文件本身推出，需要一张现场安装照片或安装基准说明。
2. **2.2 节提到的孔径数值差异（65/70/75 对比 68.5/73.5/78.5mm）**：请确认这块板是否就是生产工件，以及程序里应使用哪组数值。
3. **至少 1～2 张真实的 home 位姿 RGB 原图**（README 里也提到这一点）：用于在 Codex 开始写代码前，先跑一遍 5.2 节消歧逻辑的离线验证，确认真实光照/反光条件下椭圆拟合和最近邻匹配确实能工作，而不是等接入机械臂才发现问题。
4. **手眼验证进度**：明确当前 E7 候选之后是否已有更新的验证结果；如果没有，需要先按现有质量门（平移<5mm、法向<2°）走完验证，Stage 2 才有意义。
5. **失败回退策略偏好**：确认第 5.7 节"失败直接阻断、不自动回退点云粗定位"的默认策略是否符合你的产线容忍度。

## 附录 A：STEP 解析方法（供 Codex 复用/复核）

- 工具：`OCP`（`pip install cadquery-ocp`，纯 Python 绑定，无需额外系统依赖）。
- 步骤：
  1. `STEPControl_Reader` 读取并 `TransferRoots()`；
  2. 遍历 `TopAbs_EDGE`，用 `BRepAdaptor_Curve` 取 `GeomAbs_Circle` 类型的边，读取圆心 `Location()` 与半径 `Radius()`；
  3. 过滤条件：圆心 Z 坐标在顶面高度（本例 6 mm）附近（容差 0.01 mm）、半径 > 25 mm（排除小的螺丝过孔/圆角）；
  4. 按 (X, Y) 去重得到最终孔位表。
- 用同样方法遍历 `TopAbs_FACE` 中的 `GeomAbs_Plane`，可独立核实顶面/底面高度和法向方向，作为交叉验证（本方案已用该方法确认顶面 Z=6、法向 (0,0,1)，底面 Z=0）。

本附录方法已在本方案编写过程中实际执行并产出第 2.3 节的表格，不是理论描述。
