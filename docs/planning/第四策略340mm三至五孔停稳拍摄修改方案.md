# 第四策略：340 mm、优先每组3～5孔、停稳后拍摄修改方案

日期：2026-09-16。状态：代码已落地，实机未执行；本文的分组顺序由《第四策略选区外围孔优先分组方案》补充为外围先、内部后。

## 1. 目标与当前问题

第四策略默认拍摄高度调整为340 mm，优先每组3～5个目标孔，硬上限5孔；余数或共同视野等几何条件需要时，任意组允许1～2孔，并记录原因。机械臂到位并确认停稳后，默认等待1秒（可配置），再清理旧帧、采集点云。增加阶段进度、超时与取消处理，使长时间等待可以定位和退出。

340 mm沿用项目的相机光轴距离定义，不是TCP基坐标Z=340 mm。3～5孔指本组明确分配的目标孔，不限制画面中其他可见孔，也不代表只拍3～5帧。

当前代码核对：

- 旧实现曾使用320 mm和单组最多3孔；本次修订改为340 mm、最多5孔，并将3～5孔设为软偏好。
- 共享拍摄前已有`coarse_settle_delay_s`，默认0.6秒，当前使用一次`time.sleep`。
- 运动函数已有控制器停稳等待；初始拍摄辅助函数还会在延迟前后复查停稳，但不能假定每个共享点云组都执行了同等复查。
- 批量点云默认丢弃10帧、采集15帧；相机取帧调用`wait_for_frames(3000)`。若连续超时，仅25次取帧等待就可能接近75秒，尚未计入运动、推理和点云计算。
- 分组器使用候选枚举与精确覆盖搜索，失败回退可能产生单孔组；需统一校验正常分组和回退结果的几何可行性、5孔上限及完整覆盖，不新增3孔硬下限。
- 当前查看到的SDK日志尾部有队列满丢帧和流关闭记录，不能据此确认卡死根因。需要结合出问题运行的最后阶段、时间戳、异常及线程栈判断。

调整高度和增加延迟不等于修复卡死，也不能单凭固定延迟证明机械振动已消失。

建议新增`coarse_direct_final_settle_delay_s`（默认1.0）；现有直接策略高度默认改为340、上限默认改为5，上限允许配置1～5以支持对照实验。不新增`coarse_direct_final_min_group_size`硬下限参数；3～5孔作为分组软偏好，配置上限小于3时遵循显式上限。普通粗定位延迟与第四策略延迟独立，避免策略切换时相互覆盖。

超时使用单调时钟。外层计时不能打断已经阻塞的SDK调用，需同步审核底层请求超时；原生调用若不能可靠返回，需要隔离在可终止的工作进程中，不能仅增加一个外层超时判断便宣称可取消。

## 3. 分组规则

1. 使用340 mm的共同视野、边缘距离、法向差和跨度约束，生成1～5孔候选组。先通过几何质量门，再优先视野余量充分、法向差和跨度较小的组合；在质量相近时优先3～5孔、减少停靠和路径成本。5孔是上限，不为凑满5孔牺牲质量。
2. 每孔只分配一次，地图Hxx编号不随分组和路径变化。
3. 统一分配全部所选孔，剩余1～2孔可直接拍摄，无需为凑足3孔强制重新分配。例如6孔可为5+1或3+3、7孔可为5+2或3+4、11孔可为5+5+1；按几何质量和路径选择，所有例子仍须通过几何校验。
4. 只选1～2孔也可启动。受共同视野、边缘距离、法向差、跨度或余数影响，任意组可降为1～2孔，允许多个小组且不限定执行位置。逐组记录小组原因及约束证据；显式配置小上限时记录配置原因。若连单孔都无法满足几何条件，则在运动前展示孔号和失败约束，不静默漏孔或放宽质量门。
5. 候选生成和搜索有计算预算、进度与取消检查。时间用尽时只接受已经找到且覆盖全部孔的合法分组；否则返回“规划超时”，不把它误报为“几何上无解”。
6. 分组预览、运动下发前、实际采集入口均检查每组1～5孔（同时不超过配置上限）、几何可行性及完整覆盖。正常分组和回退共用检查；路径优化不改变孔号，不要求小组放在最后。

组大小约束针对本次分配的目标孔，不是有效测量数量。报告同时显示目标孔数和成功孔数，逐孔依据有效帧、拟合误差等质量门判定；合法的1～2孔组不因少于3孔被判失败。失败孔不执行最终接近动作，成功孔沿用当前策略的执行规则；仅采集评估模式不执行最终接近动作。

## 4. 到位与拍摄流程

分组预览通过 → 移动到340 mm观察位 → 控制器停稳与到位检查 → 连续稳定窗口检查 → 配置延迟倒计时 → 再次检查稳定 → 清理运动期间的旧RGB-D帧 → 获取最新TCP → 15帧点云采集 → 质量检查及保存。

- 稳定检查优先复用项目已有的到位/位姿差阈值，持续检查TCP位移和姿态变化；首次建议连续稳定0.5秒。位姿数据过期、读取失败或控制器未停稳，均不得进入拍摄。
- 默认1秒从确认停稳后开始计算，是额外缓冲，不包含到位等待、稳定窗口、丢帧及正式采集时间。控制器状态和TCP稳定也不能证明所有末端微振动消失，需通过重复测量验证延迟是否足够。
- 延迟期间分小段等待并更新倒计时，响应取消；若检测到重新运动，重置稳定窗口及延迟，但整个阶段的总截止时间不重置，避免无限循环。
- 延迟完成后清理旧帧。优先使用帧序号和设备时间戳验证RGB-D新鲜度，设备时钟不能直接与主机时钟相减；无法可靠对应时使用有界队列清理及连续新帧检测，并记录依据。
- 位姿变换使用延迟及丢帧后重新读取的实际TCP。采集中监测位姿漂移，超出阈值则使该组测量失效并保存原因，禁止将移动期间点云融合为静止测量。
- 运动异常、稳定超时、位姿失效或持续相机故障终止本轮，阻止后续自动动作；普通孔级点云质量失败按现有失败记录流程处理。
- 保留“仅采集评估”入口。该入口会移动到观察位，但不执行孔位最终XY/Z接近及夹爪动作。上一轮说明中的“只拍摄不建图”表述不够准确，应统一为“仅采集评估”。

## 5. 卡住的定位与处理

每个阶段进入时立即写入日志并刷新状态：规划、运动、等待停稳、延迟、清理旧帧、采集、推理、点云计算、保存。界面至少每秒显示组号、目标孔号、当前阶段、已用时间；采集显示帧数、有效帧及连续失败次数。GUI主线程不运行阻塞任务。

为每阶段保存开始时间、截止时间、结束状态及异常。规划和采集超过预算时保留已有诊断数据；异常退出也需写出报告，不能只在整轮成功后保存。增加诊断用线程栈转储，识别卡在SDK、推理、规划或文件写入的位置。

取消后不再下发新的运动命令；已经执行的运动使用项目已有受控停止接口处理，确认状态后结束。取消失败或底层调用无响应需明确显示，不能仅将界面改为“已停止”。

## 7. 验收

- 参数：默认340/上限5孔/延迟1秒生效，上限1～5可配置；不合法组大小和延迟被拒绝；预览、实际移动及报告一致。
- 分组：覆盖1～12孔、跨行/边缘/不可见布局、无解及规划超时；验证1孔、2孔独立执行、5+1、5+2、5+5+1及中间存在多个小组的布局。每组1～5孔且不超过配置上限，小组原因可追溯，路径优化不受尾组限制，孔身份不变、无重复或遗漏。
- 质量：验证质量较好的3孔组不会仅为凑5孔被替换为边缘余量较差的组合；合法1～2孔组正常参与逐孔质量判定，不足有效帧的孔仍失败，不为凑成功孔数降低质量门。
- 时序：模拟机器人未稳、延迟中再次运动、位姿失效、旧帧、采集中漂移，确认正式帧只在停稳延迟和新鲜度检查通过后进入计算。
- 故障：断帧、连续超时、慢推理、取消和运动错误均有明确阶段与报告；超时不会进入无限重试，GUI能持续响应。
- 实机：先固定340 mm和1秒延迟，使用仅采集评估，对同一批目标孔比较上限3孔与上限5孔的多轮结果，保持相机参数、帧数和质量门一致，记录实际组大小和画面位置。若上限5仍全部分成3孔以内，不能据此判断5孔拍摄效果。比较重复性、成功率和耗时，再固定分组对比1/2/3秒延迟，避免同时改变多个因素。覆盖任意位置1～2孔组的运行；没有独立参考值时不宣称绝对精度提升。

实施顺序：先补阶段日志、超时和诊断信息，用出问题的运行定位卡点并针对原因修复；再改340 mm、质量优先的1～5孔分组及默认1秒延迟，接入停稳复查与帧新鲜度检查；最后完成回归及上述实机对照。卡死修复与精度验证分别验收，参数修改或一次成功运行不能替代卡死根因结论。
